# Stratagem specification

WoW Forever gear guide. Target client: `D:\WoW\World of Warcraft\_forever_`, interface 16001 (listed first in `Stratagem.toc`). Gear is one list for the character's faction. It shows quest rewards, dungeon drops, crafts, world drops, and reputation rewards that beat what you already have for the selected spec, within 3 levels. Professions has a Guides tab and one tab per profession this character has recipes for. The tab name is the name the client reports. Each tab lists that profession's vendor, quest, world-drop, and reputation recipes. A reputation recipe is grouped as the faction and Vendor. Guides lists one 1–300 guide per profession this character has. When Polestar and Polestar_Guides are loaded, that 1–300 guide follows the Polestar route for the skill line, including the crafts and reagents that route names. Reputation lists those upgrades, one speed guide per faction, and the reputation recipes for professions this character has. A faction Polestar already routes uses that route through exalted. The open step shows the standing bar the client reports, from 0 to the width of the current standing. Leveling, beside Gear, lists Polestar's zone routes. Those routes already run through level 60 where Polestar has them. Gear stays the list that opens. Stratagem still does not pick a route for the character. Level BiS is the best piece for that spec you can wear at the current level. Upgrade is still worth taking. The endgame top-10 rank does not set that badge. A higher item level is not enough.

## Player-facing behavior

- Window: left categories, center steps or a guide list, right detail. Dark navy panels, violet actions, gold labels. Each list has a scrollbar on the right. Drag the thumb, or click the track, to move. The mouse wheel still scrolls. The bar sits above the rows so a row does not take the click. Categories, in order: Gear, Leveling, Professions, Reputation, Exploration, Legacy, Collectibles, Level 60 BiS, Attunements, Options. There is no Dungeons category, no Favorites category, and no All guides category. A saved `all`, `dungeons`, or `favorites` category becomes Gear. Dungeon drops stay on Gear's World Drops tab. The Gear category id is still `leveling`, so an older save opens Gear. Leveling is category id `routes`. It is a list. It does not open a route on its own.
- Gear opens that faction's upgrade list immediately. It does not ask the player to pick a zone, and it does not walk accept, complete, and turn-in steps. The player chooses where to level. Five tabs filter that list: Quests, Profession, Auction House, World Drops, and Reputation. The choice is saved on the account. Each line is one optional pickup. A line shows only when that item beats what the character already has equipped or in their bags for the selected spec, and the pickup is within 3 levels. Equipped gear and bags 0 through 4 count. The bank does not. An empty slot counts. The same item level is not an upgrade. A higher item level with the wrong stats for the spec is left off. Cloth does not replace leather, mail, or plate. For rings and trinkets, a new piece has to beat the worse of the two you would wear. One owned ring or trinket still leaves the other slot open. If the character already has a better piece, already has that item, or has turned the quest in, the line is marked done and left off. A Done click stays done across tab changes. Changing gear, bags, professions, or level runs that check again. The first line, when the selected tab has nothing, says so for that tab. While this tab still has pieces within 3 levels whose stats have not arrived, and nothing on the tab is ready to show, that line says the items are still loading. Pieces that have already loaded still show. Stats are read with C_Item.GetItemStats, using item: and the item id, once the client has cached that item. The older GetItemStats global is only a fallback. The addon asks for up to 64 uncached pieces at a time, and only for the open tab. A stat table with no numbers is ignored until the item is cached, so an unloaded item is not treated as an empty upgrade. After it is cached, an empty table counts as no spec stats. A piece the client rejects, or that is still uncached 20 seconds after it was asked, is left off. Pieces more than 3 levels ahead are not requested.
- A quest line is added only when the catalog, QuestieDB, or the journal chain names that quest, and at least one reward is gear this class can wear. The pin comes from the catalog, or from the journal start when the catalog has no pin. Reward ids come from the catalog and from QuestieDB item quest rewards. A Naowh source that points at a quest is included the same way. A quest with no name is left off. The line's level is the catalog level, then the Questie quest level. If neither names a level, the line stays at 1. When that reward is an upgrade, the earlier quests that lead to it are listed above it under one header, Chain: and the reward quest's name. Each of those quests is its own line, and the text says it leads to the reward. A choice the chain lists beside other quests says to complete one. The reward line stays last and still names the item to take. A quest line, including a chain lead, says to get that quest and then names the zone, the quest giver, and where to find them. The zone is the catalog zone, else the zone on the quest's where line, else the client name of the start map. The giver is the name on that where line when it is a short name, else the journal chain start, else the first starter QuestieDB names, an npc before an object. The place is the catalog or journal start, in 0–100, else that starter's spawn once ZoneDB has a ui map for the area. A part none of those name is called out as not named. Nothing is filled in from memory. Set waypoint uses that same map point. The chain shows only while that reward is an upgrade on the Quests tab. A turned-in step in the chain stays marked done. A manual Done click stays done. A quest with no name in the catalog, QuestieDB, or the journal chain names is left off. The ids come from the journal lead, prerequisites, and series, then Discovery requirements that already have a name. A later quest that only requires a chain step is not pulled in. Follow-ups after the reward are not listed as lead-ins. When an earlier quest in the same chain also gives gear, the later chain starts after that quest, so a quest is listed once.
- Dungeon lines come from the journal loot table, one step per item this class can wear. The text names the boss and the drop percent. Trash has no percent. A missing percent says "no percent in the journal". The level is the journal bracket, or higher when the item cannot be worn yet. The pin is the dungeon entrance. Without the journal, those lines are absent. Nothing invents a boss, an item, or a rate.
- Craft lines come from the loaded recipe list, and from a Naowh source whose text says Crafted. The profession name comes from the profession spell, or from the source text before the middle dot. The note names the skill, the trainer, the vendor, or the first drop mob only when the recipe names them. If the profession is missing, the line says the list does not name it. A craft that is also a quest reward stays on the quest line. Numbers on a drop tuple are not used as coordinates. The Profession tab lists crafts from professions the character has, including bind-on-pickup and bind-on-equip. The profession match is the skill line from the client, the same id the recipe list uses. A short skill still shows the line, and the note still says what the recipe asks for. A bind-on-pickup craft from a profession the character does not have is left off. A source that only says Crafted, with no profession id, is not treated as the character's profession.
- World-drop and auction lines come from the loaded Naowh source list. Bind type comes only from C_Item.GetItemInfo, return 14, with GetItemInfo as a fallback: unbound and bind-on-equip can be bought from another player. Bind-on-pickup, bind-on-use, and an unknown bind are not put on the Auction House. The addon does not guess a bind type or an auction price, and it does not read the letters boe out of a source string. Auction House shows bind-on-equip crafts from professions the character does not have, plus world drops the client marks unbound or bind-on-equip. A source that itself says auction stays on that tab even when the bind is not loaded yet. A bind-on-equip world drop is listed on both Auction House and World Drops, and both show the farm line. World Drops also lists dungeon drops, under the dungeon name, with the boss and the journal percent. Trash still has no percent. The same item is not repeated when it is already a quest, dungeon, or craft step.
- Vendor gear is not listed. Scanning every vendor weapon and armor kept the client from returning item stats, and the gear tabs then looked empty. Each profession tab still lists that profession's vendor, quest, world-drop, and reputation recipes. A price is not invented.
- The Reputation tab lists class-usable gear from the dungeon journal's reputation factions, within 3 levels, using the same upgrade test as the other tabs. A recipe on that faction's reward list is not gear. A consumable with no equip slot is not gear. Unreleased factions are skipped. Each reward is grouped under the faction name. The quartermaster name, map, and price come from that faction's journal row. The pin stays in the journal's 0–100 coordinates. While one of that faction's rewards is a visible upgrade, the journal's turn-ins for the character's faction are listed above it. The text names the turn-in, the items it takes, the reputation it grants, the place, and the mobs the journal stored. It does not invent the rest of the mobs. A hand-in does not mark that step done. The turn-ins leave once the character's standing already meets every visible reward on that faction. A faction the character has not discovered yet keeps its steps. The saved tab id `reputation` stays selected. A saved `vendor` still becomes Quests.
- The Reputation category, above the old capital lists, has three kinds of guide. Gear Upgrades is the same reputation gear, grouped by faction, without the hand-in steps. Professions is the reputation recipes for a profession this character has. The journal decides which recipe belongs to which profession. A learned recipe leaves when QuestieDB names the spell it teaches and the character knows that spell. No spell is invented. Each remaining journal reputation the faction filter can show gets its own guide. When Polestar has a route for that faction id, the guide is that route instead of the quartermaster and the journal turn-ins. The steps stay on the list. A step is marked done once the character's standing has passed the standing that step is working toward, and every step before it is marked done too. At exalted, every step is marked done. The first step that is still open shows the standing bar the client reports, from 0 up to the width of the standing you are on. Friendly can be 0–6000 when that is the bar the client returns. The addon does not hardcode that width. Dungeon runs, cloth turn-ins, and other farms stay when that route names them. Steps are grouped by the standing they lead to. A faction Polestar does not route keeps the quartermaster, then each turn-in for that side, open until exalted. A faction with neither is one note that the journal has no steps. A Polestar reputation route whose faction id is not already on the journal list is added too. A guide that names two factions, such as Warsong Gulch, is split so each faction id only gets its own steps. A city route that is the other faction is not used. Horde capitals and Alliance capitals stay where they were. These guides do not ask the item client at login. They ask, up to 64 at a time, only while Reputation is the open category, the Reputation gear tab is selected, or a reputation guide is the active guide. Standing changes refresh the bar. They do not rebuild the guide list.
- A world drop names the mob with the highest percent in the QuestieDB wowhead drop list, that percent to one decimal, and about how many kills that percent takes. The kill count is `ceil(100 / chance)` from the real percent. The line then says how many of that mob Stratagem has recorded for this character. The count starts when the addon is recording. It is not a lifetime total from before that. A kill counts when the combat log says the player or the player's pet made the killing blow. If that drop list has no percent, the line says so. No mob, percent, or old kill total is invented.
- Wrong class, race, or faction is left off. Mail is not a hunter or shaman upgrade before level 40. Plate is not a warrior or paladin upgrade before level 40. The endgame rank is not a filter. Switching spec can change which piece a choice quest names. It does not add a quest the class cannot wear.
- The arrow and the tracker land on the first listed upgrade that is not done. Gaining a level or changing gear refreshes which lines are visible. It does not mark the remaining lines done. A line more than 3 levels out stays hidden and is not marked done. Stepping back with Prev stays put until Next or Done.
- Login selects the faction gear list whenever Gear is the open category, including after an old All guides save. The arrow follows that list, not a leftover dungeon or profession guide. The window opens on its own only when this character had no saved guide. Right-click the tracker or the HUD arrow to open Gear. Clicking Gear in the sidebar does the same.
- Selecting a guide, or logging in with auto-advance on, reads completed quests and the quest log. Accept is done when the quest is in the log or turned in. Complete is done when the objectives are done. A dungeon Run step is done when every quest on it that is still shown has its objectives done, or is already turned in. Turn-in is done only after the hand-in. On Gear, a quest line is done only when that quest is turned in. Accepting it is not enough. A dungeon, craft, or world-drop line has no quest, so it closes when the worn piece is already better, when that item is in your bags, or when Done is clicked. Turning one quest in does not finish the others. A failed quest stays open. Optional gear quests are included in that check. Farms are not. Chat reports a skip count only when the player selects a guide. Prev stays on the step it returns to until that guide is selected again. Old per-zone progress does not carry onto the new route id. Catch-up fills it from the quest log. When the route's step list changes, that character's checkmarks on the route are cleared once so the old indexes cannot land on a different quest. Catch-up fills them again from the quest log. The HUD and the detail pane list every objective line from the quest log on a Complete step and on a Run step, including the client's `0/12` count when it provides one. There is no line cap. The tracker grows with those lines, and the mouse wheel scrolls them when the card would be taller than the screen. The detail pane gives that text all the room above the buttons and any reward rows that are showing, and the mouse wheel scrolls the rest. Until the quest is in the log, the line says the objectives show up then. It does not invent a kill or a gather line. A quest that continues earlier quests shows a chain marker on the tracker, on its step row, and on the detail title. Mouse over the marker for those earlier quests, in order. The first quest in a chain has no marker. A dungeon Run step's marker lists each chained quest on that clear and the quests that lead to it. A Turn in step on the HUD still shows up to four reward rows: icon, name, and Take · Level BiS, Take · Upgrade, or Skip. The guide step row shows one item icon, then the step title. The detail buttons do not list reward items. Mouse over the icon for the item tooltip.
- Spec is chosen in the sidebar or with `/sg spec <key>`. Keys match NaowhForever_BiS. Auto-detect uses the classic talent tab. Feral tank shares tab 2 with feral DPS and stays a manual choice.
- Wrong class, race, or faction is never shown. "Hide rewards meant for other specs" hides outdoor quests the endgame list ranked for a different spec. It does not hide a pickup that is part of a dungeon clear. A journal quest that the top-10 ranking slice names for nobody stays visible. Gear still shows an upgrade this class can wear when that list ranked the quest for another spec. Turning that option on or off, and Show every spec, only reapplies that visibility. It does not rebuild Gear, recipes, collectibles, or the other generated guides.
- The Gear list is the upgrades for the selected spec. Stats that spec wants are read with C_Item.GetItemStats once the client has cached that item. Caster specs also count spell damage, spell healing, and spell power when the client reports them. Melee specs count attack power the same way. A missing stat adds nothing. Gold and the label Level BiS mean that item's spec score is at least as high as the other pieces you can wear now in that slot, and it beats what you already have. Green and the label Upgrade mean it still beats what you have, and a stronger piece for that slot is already available at your level. Mail is not hunter or shaman gear before level 40. Plate is not warrior or paladin gear before level 40. A quest the character cannot accept does not count. The endgame rank is not shown on a Gear line. Equipping a better piece, or already having that item in your bags, marks the line done and leaves it off. Take the piece off, or get rid of the bag item, and the line comes back. Turning the quest in stays done. The step ids are rebuilt when Questie reward data arrives, not on every equip. A Done click stays done. The progress count covers the selected tab. Lines on the other tabs stay off that count.
- Item names come from the client or from QuestieDB. If neither has a name, the line says item and the id. A quest, boss, vendor, recipe, or auction price is never invented. Zone writeups remain in Guides.lua and are not opened. The player chooses where to level.
- Level 60 BiS sits above Options and opens its steps immediately. There is one required step for each equipment slot, in a fixed order, using rank 1 from the loaded Naowh list for the selected spec. The text says where that item comes from. A quest source names the quest and the place. A dungeon source names the boss, the dungeon, and the journal percent when one exists. The words "Buy it on the auction house" appear only when the source text itself says auction. A world drop says the list does not call it an auction listing. A drop, an auction listing, or a quest reward shows that item's icon on the step row and on the tracker. The next step is an optional enchant for the rank 1 piece in that slot. The line names the enchant from the Naowh list, including head, shoulder, waist, and leg enchants when that item can take one. It does not depend on the item you are wearing. A slot with no enchant on that list says so. The first step and the detail line show the current gear score and the score of these rank-1 pieces. The ideal number can rise while item links are still loading. Without NaowhForever_BiS the steps say the list loads with that addon. No enchant, boss, or auction price is invented. Changing spec rewrites the item text and does not change the step count.
- Attunements is a list, not an auto-opened route. The guides are Onyxia Attunement for Alliance (journal quest 6502), Onyxia Attunement for Horde (6602), and Molten Core Attunement (7848). The steps are the journal prerequisite list, then the journal series, then that quest, with duplicates skipped. When the journal lists several quests as alternatives, one step names them and asks the player to complete one. A quest the journal does not list is not added. If the journal is missing, the guide is one note that says to enable NaowhForever_DungeonJournal. The faction filter hides the other side's Onyxia guide. Molten Core is both factions.
- Professions keeps Guides, and one tab for each profession this character has recipes for. The tab name is the name the client reports, including cooking, fishing, and first aid when those professions have recipes. The choice of Guides or a profession is saved on the account. Guides is the list: one 1–300 guide per profession, then the crafting quests. The profession tabs are not extra rows on that list. Opening one shows only that profession's vendor, quest, world-drop, and reputation recipes. A reputation recipe is grouped as the faction and Vendor. It names the quartermaster, the zone, the map point, and the standing when the dungeon journal has them. A recipe the journal lists is not repeated as a plain vendor line. Trainer recipes are not listed. A vendor line is one seller whose faction matches the character. It names the seller, the price, and the reputation standing only when the recipe list has them, and it pins that seller. A quest line is one quest whose side matches the character. It names the quest, the giver, the level, and the zone only when the list has them, and it pins the giver. Turning that quest in does not finish the line. A world-drop line names the mob, the zone or instance, and the map point Forever Guide stored for that mob when it has one. The percent is the classic chance Forever Guide ships with its item search. It is not a Forever Wowhead rate. A full Wowhead Forever drop table was not available, so those rates are not shown. A player sighting with no percent says so. An instance whose stored point is the entrance keeps the instance name and says which zone that entrance is in. A bind-on-equip world drop adds the last auction price Auctionator scanned for that item. No price is invented. If Auctionator has no scan, the line says so. A recipe the character already knows is marked done and leaves the list. A mob Forever Guide marks friendly to the character's faction is left off. The pin is that mob's stored map point when the numbers are 0–100. When the snapshot has no row, the line uses a QuestieDB drop-list percent if that item is in it, then the recipe list's own mob, zone, or percent, then a short Questie mob list with no percent. A world drop none of those name says so. Dungeon drops stay under World Drops. A world drop with no area omits the place. Headers on that tab read Vendors, Quests, or World Drops, then the zone or dungeon when the list names one. A reputation header is the faction and Vendor. The step count is that profession only. A learned recipe is marked done and leaves the list. Inside a place, the order is the skill the recipe asks for. Without NaowhForever_Professions the guide says that list is missing. With no profession learned, it says to learn one. Adding the quest lines changes the step list, so checkmarks on Recipes clear once, and a learned recipe fills back in. Opening a profession reads the bind type for that profession's world drops only, up to 16 uncached items at a time. A row icon uses the client icon lookup and does not ask the item cache to load every recipe. An item reply does not repaint the whole window unless that recipe was one of the items asked for.
- Each profession the client reports, including cooking, fishing, and first aid, also gets a guide titled with that profession and 1–300. When Polestar has a route for that skill line, the steps are that route, in the guide's order, through skill 300. A step names the zone, the trainer, or the craft. A craft names the recipe and the reagents that route lists. Race and faction filters on the route are kept, so a Human does not see the Dun Morogh or Durotar opening. Earlier steps are marked done once the character's skill moves into a later range, reaches the end of the range, or reaches 300. The arrow sits on the first open step of the range the skill is in. Without a Polestar route for that skill line, the steps fall back to the older lists. The header is the zones those lists name for that range. Herb and ore zones come from NaowhForever_QoL Glimmer spots, joined to the node skill on that object. Fishing zones come from `ns.FishingLevels`: the low skill is where that water opens, and the high skill is where the list says no fish gets away. A range past 300 is cut off at 300. Crafting steps use RecipeData. A trainer recipe the list places in one zone is pinned there. When the list does not name one zone, the step pins one trainer for the character's faction and says the pin is that trainer. Vendor, drop, and quest recipes use the zone on that row. A row with no zone is left off. Rank steps name the trainer, vendor, or quest the rank row names. Skinning, or any profession the lists do not place, is one note that no zone is on the list. Nothing invents a bracket, a zone, a node, a trainer, or a reagent. The arrow then lands on an open rank the character can learn now, otherwise the latest herb, ore, or fishing range, otherwise the latest craft range. Gaining skill does not rebuild the step list. Learning or dropping a profession, or Polestar finishing its load, does. Checkmarks clear once when that list changes, then the current skill fills the earlier ranges again. Each profession tab is that profession's vendor, quest, and world-drop list from RecipeData. It is not the 1–300 route.
- Leveling is the category beside Gear. It lists Polestar's zone routes for this character's race and faction. A route's level range is the range on that guide, and the guides Polestar ships already include brackets through 57–60 and 58–60. A step shows the quest level when the route has one, including a quest at level 60. Turning in every required hand-in on a step marks that step done, and the steps before it. The character's level does not by itself finish a route. A step with no hand-in finishes when a later hand-in does. These routes are not woven into gear-h or gear-a. Without Polestar and Polestar_Guides, the category is one note that the routes load with those addons. Nothing is filled in past the guides those addons have loaded.
- The other categories stay lists. Each row has an Open button. Double-click or Continue opens that guide in the center pane and sets the waypoint. There is no guide tab and no Open in tab. The bar above the list is only the drag handle and the close button. The search box filters the list on screen. On a guide list it matches the guide. On an open guide it matches the step title, the step text, the header, the place, the drop line, and the item name. It does not leave the open guide. Options stays on Options. The faction is the character's. There is no faction switch. Guides marked for both sides still show.
- Legacy stays a list. Class quests remain the class-only BiS quest guide. Beside that, each achievement the client files under a Legacy category and that awards a point is its own guide. The guide title is the achievement name. The step text is the achievement description, the reward sentence when the client has one, and the criteria lines, including a count when the client reports one. A finished achievement is marked done. Pin on that step tracks it in the pin window. The same name and description from another ruleset is one guide, and it is done when any of those achievement ids is complete. If the client does not name a Legacy category, a reward sentence that says Legacy is used instead. If neither names a point award, the category has one note that says the list was not there. No challenge name, id, or point value is written into the addon.
- Collectibles opens one guide, Mounts, pets, and toys. It does not move the HUD arrow until Continue or a click on a step. A line is one mount, pet, or toy a loaded list names that this character has not collected. The header is the kind, the place name when a source names one, and Vendor, Drop, or Quest when the source says so. A reputation vendor is Vendor. A place the source does not name is left out, so a header can read Mount - Vendor. The detail is the journal source or description, the quest name and its objective lines, a drop-list percent when the drop list has one, or the standing and price the journal lists. It does not invent a walk, a boss, or a percent. A collected mount, pet, or toy leaves the list. When nothing uncollected remains, or nothing was listed, one note says so.
- A step row shows the item icon, then the step title. The line under it still shows the level, optional, Level BiS or Upgrade, the gear name, the quest giver, the drop line, the place, and the coordinates. The detail pane keeps Set waypoint, Mark done, and Next step, plus Pin. It does not list reward items under those buttons. Pin adds that step to a separate window. The main tracker stays on the active guide. A pinned quest lists its objective lines. A pin with no quest lists the step text, up to eight lines. Unpin removes it. Open on a pin opens that guide and sets the waypoint. The pinned window hides when nothing is pinned. Drag moves it unless Lock the tracker in place is on. Left-click on a pin does not move the HUD arrow.
- Set waypoint places a marker on OpenMap when that addon is loaded and the step has a map id and coordinates. The point is the step's 0–100 coordinates divided by 100, the same scale TomTom already uses. OpenMap's own track call draws the marker and, when the map allows it, sets the Blizzard user waypoint. A step with no map point does not invent one. Clearing the step removes the marker Stratagem placed. TomTom gets a waypoint when its option is on and the step has a map id. When OpenMap already added that TomTom pin, Stratagem keeps that one pin instead of adding a second. With the TomTom option off, that extra TomTom pin is removed and the OpenMap marker stays. The HUD arrow still shows. It points at the tracker's current step, names that step, and prints the distance in yards. Prev, Next, Done, and a click on a step move it. Left-click drag moves the arrow, and the spot is remembered. Right-click opens Gear. Direction and distance come from one vector. With HereBeDragons, that is `GetWorldVector` from the player to the pin, the same call TomTom and RXP use, then the player's facing is subtracted. Without it, the client's world position is used with that same angle formula. On the same map, without either, it estimates 42 yards per map percent and treats east as +x and north as −map y. Walking the way the arrow points reduces the yard count. `/sg arrowflip` mirrors the arrow (left becomes right). It does not rotate it 180 degrees. A step with no coordinates does not raise the arrow. A Run step pins the journal entrance and super-tracks the first quest on that clear whose objectives are still open. Steps that share one camp pin keep the same direction until the route leaves that pin.
- Slash: `/stratagem` and `/sg` with show, hide, tracker, next, prev, done, waypoint, spec, status, reset, reset all, arrowflip. Keybind: Toggle Stratagem.
- Saved variables: `StratagemDB` (account, including the Gear tab and the Professions tab) and `StratagemCharDB` (character, including recorded kill counts).

## Data

- Live source, when loaded: `_G.NaowhForever` or `_G.NaowwahForever`, `Journal.BiSQuestData` plus `BiSData` spec rankings. Dungeon tags are copied from the snapshot onto live rows by quest id. Level 60 sources, enchants, gear score, dungeon loot, and attunement chains are read from that addon at runtime. They are not copied into this repo.
- Bundled snapshot: `Data\Quests.lua` and `Data\ItemSpecs.lua`, generated by `Tools\build_catalog.ps1` from the local Naowh journal and BiS list. 131 quests, about level 6 through 34. Higher brackets only contain quests that exist in that range. No quest id, item id, boss name, or drop chance is invented.
- Zone writeups live in Guides.lua as source data. They are not opened. Gear.lua builds gear-h and gear-a in the leveling category. Profession, reputation, exploration, dungeon, and the other dynamic guides are still compiled on their own. Level 60 BiS stays guide bis-60.
- A segment may also carry `plain` quests. Engine marks those steps `path`. They are filtered by class, `notClass`, and race, then shown even when the spec filter is on. The accept text calls them starting-zone quests. `Gear.lua` appends the reward sentence once QuestieDB has been scanned. Without QuestieDB those steps cannot name a reward. Catalog quests still can, from the reward ids already on the quest row. A catalog entry may be `{ id, class, races }` instead of a bare id. Compile copies the catalog row and applies that class or race. `races = false` clears the mask. The catalog row itself is not edited.
- Gear score uses `ns.NaowhScore` when Naowh is loaded. The current number is the player's score. The ideal number is the score of the rank-1 item links, falling back to the equipped item while a link is still loading. It is not the level-60 formula curve.

## Files the client loads

`Stratagem.toc`, `Bindings.xml`, `Core.lua`, `Specs.lua`, `Data\Quests.lua`, `Data\ItemSpecs.lua`, `BiS.lua`, `Gear.lua`, `Data\RecipeDrops.lua`, `Recipes.lua`, `Polestar.lua`, `ProfPath.lua`, `Reputation.lua`, `Guides.lua`, `Collectibles.lua`, `Legacy.lua`, `Route.lua`, `Engine.lua`, `Nav.lua`, `UI\Theme.lua`, `UI\Widgets.lua`, `UI\Minimap.lua`, `UI\Tracker.lua`, `UI\Pins.lua`, `UI\Window.lua`, `Media\`.

QuestieDB is an optional dependency. Stratagem reads `_G.ItemDB` and `_G.QuestDB` from it. It does not copy that database into this repo. NaowhForever, NaowhForever_BiS, NaowhForever_DungeonJournal, and NaowhForever_Discovery are optional. Without the first three, farms, Level 60 BiS, and attunements say what is missing. Discovery is read at runtime from `CompletoQuestData` and is not copied into this repo. Without it, a lead-in the journal does not name, including The Barrens Oases, is left off. Polestar, Polestar_Guides, Polestar_Codex, Polestar_Nav, and Polestar_QuestDB are optional. Stratagem reads `Polestar.Guides` at runtime. It does not copy those guides, and it does not read Polestar's item database.

## Current limits

Gear can only name a quest reward the catalog or QuestieDB lists, a dungeon drop the journal lists, a craft the recipe list or a Crafted source lists, a world drop or auction line on the loaded Naowh source list, or a reputation reward the dungeon journal lists. It does not list vendor gear. Reputation steps, prices, and pins exist only when NaowhForever_DungeonJournal is loaded. A faction, turn-in, mob, or price the journal does not list is left off. PvP ranks are not part of these guides. It does not choose where to level. A piece more than 3 levels ahead stays hidden. Without QuestieDB, quests that are not in the catalog cannot name a reward and are left off, and a world drop says the drop list has no percent. Without the dungeon journal, dungeon drops are absent. Without the recipe list, crafts come only from source lines that say Crafted, and the Recipes guide says the list is missing. A profession 1–300 guide uses the Polestar route for that skill line when Polestar has one. Otherwise it names a zone only when Glimmer, FishingLevels, or RecipeData already has that zone. A profession those lists do not place is one note. No skill bracket, zone, recipe, or reagent is invented. Craft names and reagents on a Polestar profession step are the ones that guide already stored. Each profession tab uses RecipeData vendor, quest, and world-drop rows for that profession. World drops also use `Data\RecipeDrops.lua`, a snapshot of Forever Guide's item search, dungeon names, and player sightings for those recipe items. The percent in that snapshot is Forever Guide's classic chance. A row with no percent had no percent there. It is not a Forever Wowhead rate, and it is not copied from Questie's full drop table. When that snapshot has no item, a QuestieDB drop-list percent is used if the item is in it, then the recipe row, then a Questie mob list of at most 8 with no percent. A longer Questie list says how many mobs it names and does not pick eight of them. Trainer, teacher, and unknown rows stay off. A vendor, quest, zone, or mob none of those sources name is left unnamed. There is no WoWhead dump in this repo. A reputation speed step exists only when Polestar's route for that faction names it, or, when Polestar has no route, when the journal lists that quartermaster or turn-in. A Leveling route, a quest level on it, and a step past level 30 exist only when the loaded Polestar guide already has them. Later game updates can replace those guides. They are not filled in from memory here. The Dungeons sidebar category is gone. Dungeon drops remain on Gear's World Drops tab. The route compiler can still emit a dungeon segment when something calls it. Collectibles lists a mount, pet, or toy only when QuestieDB or a client journal names it. A percent is only the drop list's percent. A quest's objective text is shown only when QuestieDB has it. The pinned window is character saved data and does not replace the main tracker. Legacy challenge guides exist only when the client's achievement categories name them. A challenge the client does not list is absent. Show every spec does not rebuild the guide list. A profession tab asks for at most 16 uncached world-drop items at a time. Level 60 BiS, enchant plans, auction prices, and attunement steps exist only when the matching Naowh addon is loaded. Bind type is whatever the client reports. An unknown bind is not listed on the Auction House. Tracked kills are only the kills Stratagem has recorded for this character. Steps with coordinates in the text but no map id do not drop a TomTom pin or an OpenMap marker. Set waypoint marks OpenMap only when the step already has a map id and coordinates. A gear piece the client rejects, or that is still uncached 20 seconds after it was asked, is left off the open tab. Stats come from C_Item.GetItemStats after the item is cached. An empty table before that stays in flight. The loading line shows only while pieces on that tab within 3 levels are still in flight, and only when none of them is ready to show. A quest chain lists only lead-ins the journal or Discovery already names, and only while the reward is an upgrade.

## How to test this version

On the Forever character screen, enable Stratagem, NaowhForever_BiS, NaowhForever_DungeonJournal, NaowhForever_Discovery, NaowhForever_Professions, NaowhForever_QoL, Polestar, Polestar_Guides, and QuestieDB if they are installed. In game:

1. `/sg` opens the window on Gear. The center pane has Quests, Profession, Auction House, World Drops, and Reputation. There is no Vendors tab, no zone route, and no All guides button. Esc, the minimap button, and `/sg hide` close it. Switching tabs keeps a Done click done.
2. A line shows only when that item beats what you have equipped or in your bags for the selected spec, within 3 levels. An empty slot counts. A higher item level with the wrong stats does not. Equip a better piece and the line leaves. Turn the quest in and its line leaves. Accepting the quest does not. If the item was only in your bags, getting rid of it brings the line back. The bank does not count.
3. World Drops lists world drops and dungeon drops. With the dungeon journal loaded, a dungeon line names the item, the boss, and a percent. Trash has no percent. Without the journal, those lines are absent. Nothing guesses a boss or a rate.
4. Profession lists crafts from professions you have. A bind-on-pickup recipe from a profession you do not have stays off. Auction House lists bind-on-equip crafts from professions you do not have, and bind-on-equip world drops. A world drop names the percent, about how many kills that takes, and how many of that mob this character has been recorded killing. If the drop list has no percent, the line says so. The kill count is not a lifetime total from before Stratagem was recording. Dungeon drops are on World Drops and still name the boss and the journal percent. Vendor gear is not on these tabs.
5. Open Professions. Guides sits under the window tabs, then one tab for each profession you have recipes for. The label is the name the client reports. Those tabs are not rows on the Guides list. With Alchemy, that tab lists Alchemy only. A vendor line names who sells it, and the price, only when the list does. A quest line names the quest and the giver only when the list does. Turning that quest in does not remove the line. A reputation line is grouped as the faction and Vendor. It names the quartermaster, the zone, and the standing the journal requires, and it pins the quartermaster when that point is stored. A world-drop line names the mob, the classic percent, the zone or instance, and the map point Forever Guide stored when it has one. A seen mob with no percent says so. A bind-on-equip drop shows Auctionator's last scanned price when that addon has one. The subline names that mob. Learn the recipe and the line is marked done and leaves. Trainer recipes are not on this tab. The drop lines change the step list, so old checkmarks on Recipes clear once. On Guides, each profession you have has a 1–300 guide. With Polestar and Polestar_Guides enabled, that guide follows Polestar's route: the step names the zone, the trainer, or the craft, and a craft names the recipe and the reagents that route lists. Ranges below your skill are marked done, and the arrow sits on the open step of the range you are in. Without a Polestar route for that skill line, the header is the zones Glimmer, FishingLevels, or RecipeData already name. A rank you have not learned yet stays open. A profession those lists do not place is one note. No zone, recipe, or reagent is filled in from memory or from a WoWhead dump.
6. Open Reputation. Gear Upgrades and Professions are unchanged. A faction Polestar routes, such as Argent Dawn or your home city, lists that route's farms and dungeon runs, grouped by standing, through exalted. The open step shows the standing bar the client reports, such as Friendly and the have/width numbers on that bar. Earlier standings say Done. A faction Polestar does not route still lists the journal quartermaster and turn-ins. Open Leveling, the category beside Gear. It lists Polestar's zone routes for your faction, including brackets that go to 60. A finished turn-in marks that step and the steps before it. Your level alone does not finish the route. Gear does not open one of these routes for you. Without Polestar, Leveling says the routes load with that addon.
7. On an empty slot the line can say Level BiS in gold. When a stronger piece for that slot is already available at your level, it says Upgrade in green. The step row and the tracker show the item icon. The detail buttons do not list reward items. Mouse over the icon.
8. The HUD arrow names the current step and shows a yard distance. Walk the way it points and the yards should fall. Next and Prev move it. Left-click drag moves it, and `/reload` keeps that spot. `/sg arrowflip` mirrors it. Right-click opens Gear. With TomTom on, a pin is dropped as well. Set waypoint on a step that has a map point also marks that point on OpenMap. Open the map and the marker is there. A step whose lists name no point does not gain a marker.
9. On Gear's Quests tab, open a quest reward or a chain lead. The detail names the zone, the quest giver, and where to find them when the catalog, the journal start, or QuestieDB has that. A missing part says the list does not name it. The line under the quest still shows the giver and the coordinates when those exist. Set waypoint on that step marks the same point on OpenMap.
10. When the selected tab has nothing in the next 3 levels, the first line says so for that tab. "Items still loading" can show while this tab's nearby pieces are still in flight and nothing is ready yet. Upgrades that have already loaded stay on the list. It should not say there is nothing when an empty slot or a real upgrade is within 3 levels. On Quests, a reward that is an upgrade and has earlier quests shows those quests under a header that starts with Chain:, with the reward last. A chain whose reward is not an upgrade stays off the list. Gain a level, learn a profession, or take off a better piece, and a line can come back. A line more than 3 levels ahead stays hidden and is not marked done. A Done click stays done. Adding the chain steps changes the step list, so checkmarks clear once and turned-in quests fill back in from the quest log.
11. Level 60 BiS, above Options, opens slot steps without a second click. With Naowh loaded, each slot names a rank-1 item and a source. A world drop does not say to buy it. A drop, auction item, or quest reward shows its icon. Each enchant line names the enchant for that rank 1 piece, or says the list has none. The detail line shows a gear score now and an ideal after the pieces. Without Naowh, the steps say the list loads with NaowhForever_BiS.
12. Attunements lists Onyxia for your faction and Molten Core. Open one. The steps match the journal chain. A quest you remember that the journal does not list is absent. Without the journal, the guide says to enable it.
13. `/sg status` names the live journal or the bundled snapshot. The footer spec matches the character. `/sg spec` prints the key, and `/reload` keeps a manual spec.
14. Open Professions. The window should come up without a multi-second freeze, and the client should feel normal again without waiting about a minute. A profession tab still lists that profession's recipes. A bind-on-equip world drop still adds Auctionator's scanned price once the client has the bind type. Icons still show.
15. Open Legacy. Class quests is still there. Each other guide is one achievement the client lists as awarding a point. Open one. The step names that achievement and lists the criteria the client returns. Pin it. The pin window shows those lines and updates as the criteria change. Earning the achievement marks the step done. Show every spec, on a list that has nothing for this spec, should return the other specs without a one-second freeze.
